# 0007 什么才算 Track：不可替代且外部可见

- 状态：Accepted
- 日期：2026-10-12
- 范围：家族（修订 [ADR-0002](0002-track-variant-structure.zh-cn.md) 第 1 条）

## 背景

ADR-0002 规定 Track「按集成方看到的接口契约与账本拓扑划分」。实际使用中只用到了账本拓扑这一半：Track A 有公开账本，Track B 没有。

有两件事说明这个定义偏窄。

- 「有没有公开账本」这条轴最容易被替代。B.1 就是 A.1 的机密账本去掉公开账本，家族 Wrapper（[ADR-0005](0005-family-wrapper.zh-cn.md)）又能给 Track B 代币补上一个公开的 ERC-20 表面。真正搭不出来的差异在别处：状态模型（账户还是 note）与信任基础（用户持钥并在客户端证明，还是依赖外部计算网络）。
- 改变远不止账本拓扑的路线没有明确归属。[03 方案全景](../03-landscape.zh-cn.md) 把 note 模型写成「A 或 B 下的 Variant」，把 FHE 写成「A.x 或 Track C」。

有人提议把一次性收款地址方案开成 Track C 时，考虑过一种更宽的说法（「所坚持的路线明显不同」）。它无法检验：每个新想法在提出者看来都明显不同。

## 决策

1. **一条路线同时通过下面两项检验，才是 Track。**

   | 检验 | 问题 | 不通过时 |
   | --- | --- | --- |
   | **T1 不可替代** | 它的核心性质，能否在既有 Track 内靠新增一个 payload 类型、替换一个电路或增加一条客户端约定做到？能，则不通过。 | Variant 或功能 |
   | **T2 外部可见** | 它是否改变了至少一类外部参与方必须事先知道的前提？ | Variant |

   T2 所说的外部参与方是：

   - **集成方**：接口与账本语义。
   - **用户**：需要信任谁，什么必须保持在线。
   - **监管方**：靠什么方式还原账户与资金流向。

2. **不通过的是 Variant 或功能。** Variant 是既有 Track 下的新机制（要改合约或电路）。功能不需要改合约，是一个 payload 类型或一条客户端约定，记在 [07 家族级约定](../07-family-conventions.zh-cn.md) 或该 Variant 的设计文档里。

3. **Track A 与 Track B 的定义不变。** 它们仍是两种不同的集成方契约（双账本、纯机密），不重新讨论。

4. **字母不预先分配。** 只有某条路线确实要推进时才开 Track。开 Track 需要一份家族级 ADR，写明它如何通过 T1 与 T2，以及每个家族工具（Wrapper、监管视图、监管委员会）为支持它要做什么。

5. **ADR-0002 第 5 条继续有效。** 主线之外的 Track 或 Variant 只允许一页纸设计草图。

### 用两项检验评估现有候选

本表记录当前的评估结论，不代表开设任何 Track。

| 路线 | T1 不可替代 | T2 外部可见 | 结论 |
| --- | --- | --- | --- |
| 加密账户账本上的一次性收款 id | 否。按设计推导，公钥不上链（A1-0001），付款方派生一次性公钥后走普通 `0x01` 即可。尚未做原型验证。 | 否 | 功能（已预留的 `0x02` 位置） |
| 金额公开 + 一次性地址（ERC-5564 式） | 否。任何 ERC-20 的公开账本上都能做，不需要代币配合。 | 否 | 不是 Track |
| note 模型（承诺树与作废符） | 是。隐藏转账关系图、合并余额，在账户模型里换电路做不到。 | 是。寻址、钱包同步、监管还原方式都变了。 | Track 候选 |
| FHE（密文由外部网络计算） | 是 | 是。用户要信任并依赖一个阈值网络，接口也不同。 | Track 候选 |

## 备选方案

- **保留 ADR-0002 的措辞。** 被否决：它看重的恰恰是最容易被替代的那条轴，并且让 note 模型被归为 Variant，尽管集成方、用户和监管方看到的都会是另一套系统。
- **「所坚持的路线明显不同且不可替代」，不设检验。** 被否决：「明显不同」无法检验。「不可替代」这一半保留为 T1。
- **用矩阵的格子给 Track 命名**（有无公开账本 × 账户或 note × 客户端证明或外部网络）。被否决：组合数太多，大多数格子永远不会有人推进。

## 后果

- 正面：一个东西是 Track、Variant 还是功能，可以用两个问题来论证；note 模型和 FHE 有了明确位置；功能不再让 Track 数量膨胀。
- 负面：每多一个 Track，家族工具的适配工作就多一份。例如监管视图靠扫描 `ConfidentialTransfer` 事件，note 模型的 Track 需要自己的一套还原路径。
- Track 不再只是面向集成方的概念；[06 家族架构](../06-family-architecture.zh-cn.md) 里 Track 那一行相应放宽。
- [03 方案全景](../03-landscape.zh-cn.md) 的映射表里，note 模型、FHE 和隐匿地址三行有改动。
- `pep()` 描述符格式 `"<track>:<variant>:<version>"` 不变。
