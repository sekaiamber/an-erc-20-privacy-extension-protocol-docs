# 0009 开设 Track B：note 模型

- 状态：Accepted（合约与电路已于 2026-10-13 在本地实现，尚未部署；第 7 条的前提已在 2026-10-13 满足：[ADR-0008](0008-modules.zh-cn.md) 的重构已完成，dApp 里不再有任何路由对应 `B:1`）
- 日期：2026-10-13
- 范围：家族（按 [ADR-0007](0007-track-definition.zh-cn.md) 第 4 条开设一个 Track；更新 ADR-0008 的「过渡」一节）

## 背景

- ADR-0007 把 note 模型评估为 Track 候选。2026-10-12，owner 决定推进它。
- ADR-0008 撤销了原 Track B（没有公开账本的代币是 A.1 的一种组合），并释放了字母 B。
- ADR-0002 第 5 条规定，「在主线端到端跑通并给出 Gas 数据前」，主线之外只允许一页纸草图。这个条件已经满足：A.1 已在 BSC testnet 上运行并有实测 gas（[A.1 部署记录](../tracks/track-a/variant-1/03-deployments.zh-cn.md)）。因此可以为第二个 Track 写完整设计。

## 决策

1. **Track B 是 note 模型。** 价值存放在 note 里：承诺放进一棵只增不减的树，花费时公开作废符。链上没有账户。信任基础与 Track A 相同：用户持有密钥，证明在客户端生成，不依赖外部网络。文档在 [tracks/track-b](../tracks/track-b/README.zh-cn.md)。

2. **它通过 ADR-0007 的两项检验。**

   **T1，不可替代。** 在 Track A 里，每一次操作都要指明它读写哪些账户槽；状态模型本身就是这样。新增 payload 类型、替换电路、增加客户端约定或模块，都去不掉这一点。note 模型因为没有账户槽而得到四样东西：

   | 性质 | 在 Track A 里 |
   | --- | --- |
   | 链上没有付款方或收款方标识 | 每笔转账都写出两个 id |
   | 同一所有者的多笔收款无法关联 | 一次性收款 id（`0x02` 功能）只能对收款做到这一点 |
   | 合并资金不泄露任何信息 | 分散在不同 id 上的资金只能靠它们之间的转账合并，全程公开 |
   | 别人打款进来不会干扰自己花钱 | 需要 `pending` 和折叠 |

   **T2，外部可见。**

   | 外部方 | 改变了的前提 |
   | --- | --- |
   | 集成方 | `from` 和 `to` 不携带任何信息；没有事件写出交易双方；没有按账户的视图 |
   | 用户 | note 由钱包保存，钱包要处理该代币的每一笔交易才能找到它们 |
   | 监管方 | 按所有者公钥还原；一次查看覆盖整个区块区间 |

3. **第一个 Variant 是 B.1**：Poseidon 承诺与作废符，一个两进两出的 join-split 电路，Groth16。设计见 [B.1 01-design](../tracks/track-b/variant-1/01-design.zh-cn.md)。它支持角色铸造模块和 Wrapper 端口，不支持公开账本模块。

4. **Track B 的集成方契约。** note 转账的 `from` 和 `to` 是代币自身的地址。`balanceOf` 对该地址返回 `totalSupply()`，对其它地址返回 0。价值的进入和离开表现为来自和去往零地址的 `Transfer`。[07 §3 与 §7](../07-family-conventions.zh-cn.md) 为此各增加一句。

5. **每个家族工具要做什么。**

   | 工具 | 工作 |
   | --- | --- |
   | Wrapper | 合约不用改。`IPEPWrappable` 原样使用：`recipient` 里放一份创建 note 的 payload，`from` 是零地址 |
   | 监管视图 | 新写一个解码器：从监管 memo 还原 note 表，再按所有者公钥汇总 |
   | 监管委员会 | 合约不用改。客户端要认识 Track B 的事件，并从中整理出 `D` 点的列表。申请没有账户过滤 |
   | 模块探针 | 不用改。Track B 与其它代币一样报告模块 |
   | dApp | 为 `B:1` 新做一个页面，在浏览器里保存 note 并扫描 |

6. **监管在创建和花费时都强制。** 每一张 note 都由一笔带证明的交易创建，这笔交易的监管 memo 写出了它的所有者和金额，铸造出来的 note 也不例外。所以铸造虽然金额公开，仍然需要证明（ADR-0004 第 1、5 条）。

7. **字母 B 现在就占用；部署要等。**

   - 原 B.1 的文档已移到 `docs/tracks/track-a/variant-1-privacy-only/`。
   - 已部署的合约 `ConfidentialERC20B1` 仍然自报 `B:1:0.2.0`，dApp 也把 `B:1` 路由到它的页面。在 ADR-0008 的重构把该合约以 `A:1:…` 重新部署之前，不得部署任何 note 模型的代币。
   - 合约名 `ConfidentialERC20B1` 在那之前仍被占用。note 模型的合约在实现时再命名。

8. **工作顺序。**

   1. 按 ADR-0008 重构合约和 dApp。
   2. 实测链上的 Poseidon 树。它是 B.1 里最大、也最没把握的一项成本。
   3. 电路，然后合约，然后客户端。

## 接受的代价

gas 和证明时间是本地实测（2026-10-13）。其余几行是这个设计本身的性质。

| 代价 | 大小 |
| --- | --- |
| 每笔交易的 gas | 树深 24（2026-10-13 选定）时约 137 万，A.1 稳态转账是 467k。其中承诺树约占七成 |
| 证明时间 | 在 Node 里约 2.9 秒（实测，2026-10-13），A.1 是 1.3 到 1.5 秒 |
| 钱包同步 | 每个钱包都要处理该代币的每一笔交易 |
| 监管视图 | 整个区块区间；往回追查可以定点，往后追查不行 |
| 提交者 | 提交交易的地址可见。代发服务不在范围内 |

## 备选方案

- **把 note 模型归为 Track A 的一个 Variant。** 被否决：它的状态模型不同，三类外部方看到的都是另一套系统。
- **留在 Track A，只加一次性收款 id。** 作为替代方案被否决：它只能让收款之间无法关联，花费仍可关联，合并仍然公开。它仍可以作为 A.1 的一个功能。
- **叫 Track C，让 B 空着。** 被否决：项目还没有发布，B 原来的含义已由 ADR-0008 完全撤销，旧文档也都加了指向新位置的说明。
- **做一个面向任意 ERC-20 的共享屏蔽池。** 被否决：本项目研究的是代币自身。以后给这个 Track 的代币加上托管发行模块，可以覆盖那种用途。
- **铸造不带证明。** 被否决：监管方要等铸造出来的 note 被花掉，才知道它的所有者。

## 后果

- 正面：家族有了一条付款方、收款方和转账关系图都隐藏的路线，监管保证与 A.1 相同。
- 正面：Wrapper 和委员会合约都原样复用，这说明它们的接口没有绑死在账户模型上。
- 负面：多一个 Track，监管视图和 dApp 的工作量翻倍。
- 负面：在重构完成之前，「B.1」这个名字有两个含义。凡是还保留旧含义的文档都加了标注。
- dApp 里旧 `B.1` 页面的文档链接指向旧路径，需要改到 `tracks/track-a/variant-1-privacy-only/`。
- ADR-0008 的「过渡」一节相应更新：字母 B 不再空闲。
