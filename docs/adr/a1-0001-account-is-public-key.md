# A1-0001 机密账户 = 公钥，公钥不上链

- 状态：Accepted
- 日期：2026-09-24
- 范围：A.1

## 背景

加密给收款方需要其公钥，以太坊地址推不出公钥，且钱包的 secp256k1 密钥在电路中是非原生算术。最初设计以 `address → pk` 注册表解决密钥发现，但带来了开户签名凭证、stealth 场景的 griefing、花费需 `msg.sender` 持有 gas 等问题，并在链上留下公钥集合。

## 决策

1. 机密账户就是一把 Baby Jubjub 密钥，链上以 `id = address(uint160(Poseidon(pk)))` 指代。
2. **公钥不上链**。付款方链下获得 `pk_recv`，作为电路私有输入，电路证明 `Poseidon(pk_recv) → to`；付款账户同理证明 `Poseidon(pk_sender) → from`。
3. 没有注册表、没有开户动作。第一笔发往 `id` 的转账创建存储槽。
4. 私钥由钱包 EIP-712 签名哈希派生，同一钱包可用不同 index 派生多个账户。
5. `id` 与钱包地址的关联仅在公开 ↔ 机密划转时以公开边的形式出现。

## 备选方案

- `address → pk` 注册表 + 本人签名凭证：需要 `ecrecover` / ERC-1271、两级注册表防 griefing，链上暴露公钥集合。
- 直接使用钱包 secp256k1 公钥：电路内非原生算术，一笔转账上千万约束，不可行。

## 后果

- 正面：合约无密钥逻辑、无攻击面；第三方一笔转账即可"开户"；stealth 只需付款方派生新 `pk`。
- 负面：只能给链下拿到 `pk` 的账户发机密转账，无法给"只在链上见过的 id"转账（视为隐私上的加分）。`id` 是稳定化名，收付方可关联。
