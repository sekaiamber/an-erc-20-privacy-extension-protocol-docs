# A1-0007 unshield 证明通过收款人的值绑定它是给哪个出口的

- 状态：Accepted（owner，2026-10-15；在 A.1 0.7.0 中实现）
- 日期：2026-10-15
- 范围：A.1

## 背景

从机密账户按公开金额出去的每个出口，背后都是同一个电路，即 unshield 电路（01-design §5.2）：公开账本模块的 `0x04` unshield、`0x81` 销毁，以及 Wrapper 端口的 `wrapperBurn`。它绑定 `from`、nonce、代币、链、金额和 `to`（0.3.1 起，安全审查 F14），但不绑定这个证明是为三个出口中的哪一个做的。

到 0.6.0 为止这没有害处，因为各出口接受的 `to` 互不相交：销毁是零，unshield 和 wrap 是非零，而且没有任何已实现的组合同时有 unshield 和 wrap。所以 04-modules §6 没有实现公开账本加 Wrapper 端口的组合。

[ADR-0013](0013-mintable.zh-cn.md) 让一个 Variant 的模块的任意子集都成为代币，家族网关（[14](../14-gateway.zh-cn.md)）又给这个组合找到了用处：已有 ERC-20 的隐私版本，持有人也可以公开持有它。在这样的代币上，为一个出口做的证明可以从另一个出口提交。在内存池里看到持有人 `0x04` 载荷的人，可以带着同样的 `to` 和金额把它交给 Wrapper（或网关）。钱没有被偷，价值仍到了同一个收款人手里，但收款人拿到的资产不是持有人要的：本该是公开余额，结果是 wrapped 代币或锁定的 ERC-20，反过来也一样。持有人要付手续费才能换回来，而任何中继者都能对任何人这么做。

## 决定

1. **从 0.7.0 起，合约通过它传入的 `to` 值绑定出口。** 对收款人非零的出口，电路按 `to` 做范围检查的那个公开输入不再是地址本身，而是

   ```
   r = uint160(uint256(keccak256(abi.encodePacked("Casata A.1 exit", kind, to))))
   ```

   `kind` 是 `uint8`（紧凑编码里占一个字节），`0x04` unshield 为 `1`，`wrapperBurn` 为 `2`。合约和客户端必须按同样的方式编码。销毁仍是 `to = 0`，哈希产生零的概率可以忽略。

2. **`r` 由合约自己组装**，依据被调用的入口和它的 `to` 参数，就像它组装其他所有公开输入一样（01-design §3.3 第 6 项）。载荷里没有任何东西指明出口类型。

3. **不改电路。** 电路把 `to` 当成一个 160 位的值，不赋予它含义。证明密钥、验证器合约和窗口表都不变。

4. **0.7.0 的每个组合都用这一条规则**，包括只有一个非零出口的组合。这样客户端在每个 0.7.0 代币上证明出口的方式都一样，不必先读模块。

5. **事件和 calldata 里仍是原地址。** `LedgerCrossing`、`WrapperBurned`、`Transfer` 和调用参数里的 `to` 跟以前一样是收款人，只有证明的公开输入变了。

## 备选方案

- **把出口类型作为电路的公开输入。** 否决：改电路就是新 Variant（ADR-0008 第 3 条），而这个绑定不需要新的约束。
- **通过 `w1`（`contract | chainId<<160`）绑定**，把代币地址和出口类型一起哈希。否决：`w1` 负责阻止证明在另一个代币上重放，往里掺第二个用途会让审查更难。指明去向的本来就是 `to`。
- **保留冲突，不做这个组合。** owner 否决（2026-10-15）：有了 ADR-0013，它是最后一个不成为代币的子集，而网关给了它用处。

## 影响

- 正面：从 0.7.0 起，A.1 模块的八个子集全都是代币（04-modules §6）。
- 正面：把一个证明改投到另一个出口或另一个收款人，需要找到 keccak 截断到 160 位的第二原像，约 2¹⁶⁰ 的工作量。攻击者自己挑的两个值之间的碰撞没有用，因为攻击者只能改投别人做的证明。
- 负面：客户端、脚本和 dApp 在证明 unshield 或 wrap 之前要先算出 `r`。0.6.0 的证明在 0.7.0 代币上验不过，反过来也一样；版本号本来就把它们分开了。
- 负面：0.7.0 的安全审查要覆盖每个出口对 `r` 的组装。
- B.1 不受影响。它没有公开账本，它的销毁和 wrap 靠 `to = 0` 区分（B.1 01-design §5）。若某个 B.1 版本加入公开账本，也需要同样的绑定。
