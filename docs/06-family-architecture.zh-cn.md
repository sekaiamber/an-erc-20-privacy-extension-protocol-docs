# 06 家族架构

状态：`Draft`

## 分层

协议家族分四层，每层回答一个不同的问题：

| 层 | 回答的问题 | 换一个的代价 | 载体 |
| --- | --- | --- | --- |
| **家族级约定** | 一个"隐私扩展 ERC-20"在链上长什么样，怎么调用 | 影响所有 Track；走 ADR 并给出迁移说明 | [07 家族级约定](07-family-conventions.zh-cn.md) |
| **Track** | 用哪种状态模型、哪种信任基础 | 每个家族工具都要适配；写家族级 ADR | `docs/tracks/track-x/README.md` |
| **Variant** | 用哪一套电路：密码学内核，以及它隐藏了什么 | 新的验证器、新的可信设置、新的安全评审 | `docs/tracks/track-x/variant-n/` |
| **模块** | 这个代币在电路不变的前提下带了哪些合约层选配 | 只改合约 | 在 [07 §13](07-family-conventions.zh-cn.md) 登记；由各 Variant 实现 |

一条路线同时通过两项检验才是 Track（[ADR-0007](adr/0007-track-definition.zh-cn.md)，其中一个分句由 [ADR-0008](adr/0008-modules.zh-cn.md) 增加）：

- **不可替代**：它的核心性质，无法在既有 Track 内靠新增一个 payload 类型、替换一个电路、增加一条客户端约定，或者加上、去掉一个模块做到。
- **外部可见**：它改变了集成方、用户或监管方必须事先知道的前提。

任一项不通过的，是 Variant（要改电路）、模块（只改合约）或功能（不改合约）。

模块分两种（[ADR-0008](adr/0008-modules.zh-cn.md)）：

- **编译时模块**继承进代币合约，用于要读写机密状态、或改变已有函数行为的东西。公开账本属于这一种。
- **运行时模块**是外部合约，插在代币的一个**端口**上，用于自带状态、只需要端口的东西。家族 Wrapper 属于这一种。

每个 Variant 的基底是纯隐私账本。代币在自己的地址上是否还有公开账本，是一个模块。所以同一个 Track 的两个代币，`balanceOf` 与不带 payload 的 `transfer` 可能表现不同；集成方要从探针（07 §13）得知，而不是从 Track 字母推断。Variant 之间互不依赖；代码在一个 Variant 内部共享，或通过家族的运行时模块共享。

## 当前家族

```
Track A  加密账户：每个账户一份同态密文余额，用户持有密钥，证明在客户端生成
  └─ A.1  Baby Jubjub 上的 ElGamal + Groth16，账户 = 公钥                    ← 主线
       ├─ 带公开账本                 合约 ConfidentialERC20A1，pep() A:1:0.4.0   ← 原型已上 BSC testnet
       └─ 纯隐私，带 Wrapper 端口     合约 ConfidentialERC20B1，pep() B:1:0.2.0   ← 原型已上 BSC testnet
运行时模块  通用 Wrapper（10-wrapper）：为没有公开账本的代币发行 wTOKEN             ← 已部署（PEPWrapper）
家族工具    监管委员会（11）：门限监管密钥、成员、策略、审计                       ← 原型
```

第二种组合在合约、dApp 和 `docs/tracks/track-b/` 里仍沿用旧名「Track B / B.1」，直到合约重构完成（ADR-0008「过渡」）。字母 B 目前没有分配给任何路线。

## 一个代币的典型结构（A.1 带公开账本模块）

```
┌──────────────────────────────────────────────────────────────┐
│  代币合约（一个地址）                                            │
│                                                              │
│  ┌──────────────────┐   0x03 shield    ┌────────────────────┐ │
│  │  公开账本          │ ───────────────► │  机密账本           │ │
│  │  OpenZeppelin ERC20│ ◄─────────────── │  id → {available,  │ │
│  │  balanceOf/transfer│   0x04 unshield  │   pending, folded, │ │
│  │  屏蔽代币托管于本合约│                  │   nonce}           │ │
│  └──────────────────┘                  └─────────┬──────────┘ │
│                                                  │ 0x01       │
│  ┌──────────────────┐   ┌──────────────┐   ┌──────▼─────────┐ │
│  │ A1Payload 解析    │   │ BabyJubjub   │   │ Groth16 验证合约 │ │
│  │ type/flags/段     │   │ 点加 / 窗口表 │   │ transfer/unshield│ │
│  └──────────────────┘   └──────────────┘   └────────────────┘ │
└──────────────────────────────────────────────────────────────┘
                     ▲ 标准 transfer / transferFrom 选择器 + 尾部 payload
        ┌────────────┴────────────┐              ┌──────────────┐
        │ 客户端 / 中继者           │              │ 监管方        │
        │ 密钥派生、加密、memo、证明 │              │ 解 memo、重建余额│
        └─────────────────────────┘              └──────────────┘
```

家族级约定规定的是最上面那条边（选择器 + payload）以及事件、密钥派生、监管接口；框内的一切属于 Variant。左边那个框，即公开账本和 `0x03` / `0x04`，是公开账本模块；纯隐私的组合没有它。

## 演进规则

- 新增 Track：只在某条路线确实要推进时才开，字母不预先分配。需要家族级 ADR，写明它如何通过 ADR-0007 的两项检验，以及每个家族工具为支持它要做什么。
- 新增 Variant：只在换了一套电路时才算。在既有 Track 下新建目录，自带设计、规范、评估表；不需要家族级 ADR。
- 新增模块：在 07 §13 登记它的种类、接口，端口还要登记限额；然后在支持它的每个 Variant 里实现。模块绝不改电路，绝不能在部署后安装，绝不在代币的存储里运行（ADR-0008）。
- 家族级约定的变更影响所有 Track，必须走 ADR 并给出迁移说明。
- 只有主线 Variant 有实现（ADR-0002 第 5 条）。
